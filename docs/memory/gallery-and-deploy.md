# The gallery, its build and its deploy

Read before touching `package.json`'s scripts, `scripts/`, `tree.json`, `tree-meta.json`, `.github/workflows/`, or anything about how the site is built, measured and published.

## The gallery page is an external package (2026-10-19, read off the repository)

- `sketch-gallery` (`github:CostardRouge/sketch-gallery#0.0.15`, the owner's own package, archived on GitHub) is a React 18 + Vite 4 single page: it fetches `tree.json`, sorts the groups by `meta._mtime` (newest first, the date shown on the group's heading), draws a tile per sketch from `<path>/screenshot.jpeg` linking to the sketch and to its source on GitHub, and a fixed bar of social links at the bottom. Its `bin` (`src/cli.js`) runs `vite build` in its own folder, then `cp -r` of the sources named on the command line (`tree.json assets libraries utils sketches`) into its `dist`. **How to apply**: the page's chrome, texts, title, social links, font (loaded from Google) and layout cannot be changed from this repository — a change there is a new tag of `sketch-gallery` and a bump of the dependency, or a decision to vendor the page here. The package ships no lockfile, hence the second install step (`npm install --prefix ./node_modules/sketch-gallery`) the workflow runs; `tree-meta.json` (title, links) is not read by 0.0.15 — the title and the links are hard-coded in the package — and is kept for a later version.
- The build takes `baseUrl` `/` (`sketch-gallery build / …`): the page's asset paths are absolute (`/assets/index-*.js`), so the site works only at a domain's root — `art.steeve.website`, never at `costardrouge.github.io/generative-art-p5js/`, which answers 301 to the domain. Measured 2026-10-19: the `gh-pages` branch holds `CNAME` (`art.steeve.website`), the deploy action keeps it across deploys, and the custom domain lives in the repository's Pages settings, nowhere in the sources.
- `npm run gallery:deploy` is the package's own `gh-pages` publish from a developer machine; the workflow deploys with `JamesIves/github-pages-deploy-action` instead. Never run the script by hand: two writers on `gh-pages` would race.
- The built folder weighs what the sources weigh (1.5 GB, the `cp -r`): a build is about 85 s in a cloud container, almost all of it the copy. A deploy pays a 1.5 GB checkout and a 1.5 GB push of the branch.
- **Trap (2026-10-19)**: the built folder lives inside `node_modules`, so `npm ci` — which empties `node_modules` first — deletes it, and the gallery package's own dependencies with it. The order is always `npm ci`, `npm install --prefix ./node_modules/sketch-gallery`, `npm run gallery:build`, then the injections; an injection run after a fresh install crashes on a missing `dist/index.html`.
- The sketch pages in the built folder are symlinks too (`cp -r` keeps them): `inject-umami.js` writes into four real files (the gallery's page, the template, the two sketches with their own page) and the 460 symlinked pages resolve to the template, which carries the tag — checked live 2026-10-19 on a sketch page.

## `tree.json` and its dates (2026-10-19)

- `scripts/build-tree.js` walks `sketches/` for `index.js` files and writes, per group and per sketch, `meta.name`, `meta._mtime` (the folder's, then the file's `mtime`) and `path`; a sketch whose folder name starts with `_` is skipped and listed on the console. **Trap**: a fresh clone (CI, a cloud session) dates every folder at the checkout — regenerating there rewrote 1 016 lines on 2026-10-19 and would reorder the whole gallery, since the page sorts by those dates. The file is regenerated on the owner's Mac only, where the folders keep their real dates; a session never regenerates it and never commits a regenerated copy.
- Measured 2026-10-19 by comparing names, never lines (every line differs by its date): the committed `tree.json` lacks `censored-v15-sydney` (added without a regeneration) and still lists `social-media-templates-v1-basic`, removed from disk in `d6831b2` — a tile that opens on a 404. The owner's `npm run build:tree`, nothing else, fixes both (open item in `MEMORY.md`). A group whose sketches all start with `_` (`motion-capture`, three of them) is absent from the tree, so the gallery's group count is not the disk's: 46 folders, 45 groups listed.

## Audience measurement (2026-10-18, PR #3)

- Umami replaced Google Analytics on 2026-10-18. The tag is in no source: `scripts/inject-umami.js` writes it before `</head>` of every HTML page of the built folder, after the build and before the deploy — the sketch pages are copied as they are, so the built folder is the one place where every page can be reached. Idempotent (a `data-umami="audience"` marker), a page without a `<head>` is left alone.
- Settings: `UMAMI_WEBSITE_ID` (default the gallery's id in the script, public by design since it ends up in every page; **empty = no tag, nothing sent**), `UMAMI_SRC` (default `https://insight.steevepommier.com/insight` — the tracker is served under `/insight`, not `/script.js`, because filter lists block the latter), `UMAMI_DOMAINS` (default `art.steeve.website,costardrouge.github.io`; a host outside it — localhost, a fork — loads the tracker but never counts). The tag asks for Do Not Track, no query string, no fragment. The README documents the three; keep both in step.

## The icon set, the manifest and site/ (2026-10-22)

- 2026-10-22 — **The owner approved the icon set** ("lance tous les chantiers"); no mark existed, so the drawing is the 🌀 emoji's heir: a light Archimedean spiral (1.75 turns, thick stroke so the arms stay apart at 16 px) on a rounded tile, in the gallery's own two colours (`#1e1d1d`, `#f9f7f2`, sketch-gallery's `--dark-color`/`--light-color`). `scripts/build-icons.mjs` holds the drawing and writes the three SVG sources, the PNGs (16, 32, 96, 192, 512, maskable 192/512, an opaque 180 touch icon) and a PNG-in-ICO `favicon.ico` into `site/`; `sharp` is installed `--no-save` and never a dependency. **Trap**: that install prunes the gallery package's nested dependencies like any top-level install — re-run `npm install --prefix ./node_modules/sketch-gallery` before building. The maskable art needs no scaling: the spiral's extent with its stroke is under the 80 % safe radius (204.8 of 256).
- **`site/` is this repository's half of the built root**: `scripts/copy-site.js` (`npm run site:copy`) copies it whole to `dist/` right after `gallery:build` and before every injection, so a page placed there gets the tracker and the icons like the others. **How to apply**: a new file the site serves at its root (a page, `robots.txt`…) goes in `site/` at the path it is served from — never into the package.
- **The head tags go into every built page**, the gallery's and the template copy every sketch page resolves to: `scripts/inject-icons.js` drops each `<link rel="icon">` (the emoji, whose `data:` URL holds a `>` — the regex matches quoted values whole) and writes the SVG icon, the two PNG favicons, the touch icon, the manifest, `theme-color` and `apple-mobile-web-app-title` before `</head>`, idempotent on `data-icons`. Absolute paths, since the site lives only at a domain's root. A tab icon and a home-screen icon are the page's chrome, not the canvas, so the sketch pages get them too — the repository's template is never edited, only its built copy. `/favicon.ico` is served but not linked (browsers ask for it by themselves). Checked 2026-10-22 in headless Chromium: the manifest parses with no error (`Page.getAppManifest`), every icon answers 200, a sketch page still runs.
- **`display: browser`, decided**: the gallery keeps no state of its own, and a standalone launch would take the browser's back button from a visitor who opens a sketch from a tile — nothing to gain, one way to get stuck. The short name under the icon is `Sketches` (a launcher cuts past about twelve characters).

English, the gallery's language; the shape and the French-law sentences (LCEN art. 6-III, CNIL) follow `system-g`'s notice. Its look is hand-written CSS in the gallery's two colours, no web font loaded.
- **What it says was read off the code, not assumed**: the tracker (fetched 2026-10-22) sends the path (query and fragment dropped by the tag), the page's title, the referrer, the screen size and the browser's language, and skips every send while `localStorage` holds `umami.disabled` — so the switch only sets that key, mirroring the tracker's own checks (Do Not Track as `1`/`"1"`/`"yes"`, the tag present, the host in `data-domains`). The sketches' control drawer (`libraries/sketch-ui.es.js`, the owner's own) keeps its settings under `sketch-ui-settings`; some sketches ask for the microphone, a camera or MIDI; the gallery page loads Lexend Deca from Google Fonts — all three said on the page.
- **`tests/legal.test.js` holds it**: the tracker's host and domains (the switch's list must equal `DEFAULT_DOMAINS`), the tag's Do Not Track and exclusions, every `localStorage` key written by `scripts/`, `site/`, `utils/`, the sketches, the template and sketch-ui named on the page, no `umami.track` or `data-umami-event` anywhere in that code, the footer's link. **How to apply**: a change to measurement or storage fails the test until the notice says the same.

## Versions and the footer (2026-10-19)

- `scripts/inject-version.js` (`npm run version:inject`) writes a `<footer data-version="…">` before `</body>` of the built `index.html` only, after the build like the tracker: the gallery's page is generated by the external package, so the built folder is the one place the version can be shown from here, and the sketch pages are the artwork — a line over a full-screen canvas was refused. The footer is in the flow after the gallery, not fixed, because the page already pins its social bar (~64 px) to the bottom edge; its `padding-bottom` keeps the line visible above that bar at the end of the page. Idempotent on a marker, like the tracker. **How to apply**: a change to the footer's look is a change to this script; a version bump is a release pull request (rule 4), never a hand edit of `package.json` alone.
- `release.mjs` and `release.yml` are versus's, byte for byte; `node .github/release.mjs check` runs on every pull request, and `publish` on `main` makes the tag and the Release. 1.0.0 is dated the day the changelog was written, as versus did.

## Toolchain and CI (2026-10-19)

- **Node is pinned**: `.nvmrc` = 24, read by `ci.yml` and the deploy workflow through `setup-node`'s `node-version-file`; `engines.node >= 22` is the floor (the container that adopted the spec ran 22.22 and every command held). No Docker image here, so no exact tag to raise.
- **Biome 2.5 lints `scripts/` and `package.json` only**, with the recommended rules (`rules.preset: "recommended"` — the older `rules.recommended: true` is deprecated in 2.5 and reports an info on every run), in `biome.jsonc` because the scope deserves its comment. Measured before scoping: `sketches/` 13 501 errors, `utils/` 12 errors and 72 warnings, `scripts/` 1 warning and 5 infos. The art stays out by decision (the owner's hand-written work, `MEMORY.md`); the five infos (`node:` protocol) were applied by Biome's own fix and the warning (a dead `getScreenshot`, superseded by `getScreenshotWithURL`) removed. The formatter is off (`formatter.enabled: false`): a repo-wide reformat is its own pull request, and while it is off `biome format` exits 1 with a diagnostic and touches nothing — so there is no `format` script; it comes with the formatter, the day that reformat lands. **How to apply**: a new script goes in `scripts/` and must pass `npm run lint`; a rule a script cannot satisfy is disabled in `biome.jsonc` with its reason, never by widening or narrowing the scope.
- The lockfile written by npm 10.9 holds all eight `@biomejs/cli-*` platform packages — checked, because `spotify-calendar` met a lock written by npm 10 that lacked the non-Linux binaries and failed `npm ci` under npm 11. If a future lock is regenerated, check that list again.
- **A top-level `npm install` prunes the gallery package's nested dependencies** (102 packages removed when Biome was added): `npm install --prefix ./node_modules/sketch-gallery` must follow every install, not only `npm ci`.
- **`ci.yml`** (every pull request, every push to `main`, `workflow_dispatch`): `npm ci`, `npm run lint`, the package's own install, `gallery:build`, both injections, then a `grep` that proves the version footer is in the built page. No deploy, no previews (the owner's Mac). Each run checks out the whole repository, 1.5 GB; `timeout-minutes: 30` and `cancel-in-progress` on pull requests keep that in check. The runner is named `ubuntu-24.04`, as in every repo of the portfolio.
- **The deploy workflow** kept its name, trigger, permissions, concurrency, the two injection steps and the Pages action with its inputs — what it publishes is unchanged; it gained `setup-node` on `.nvmrc` with the npm cache, `npm ci` in place of `npm install`, the named runner, a timeout and `actions/checkout@v7`. The actions are on their current majors (v7; the siblings run them), not the v5 the adoption brief named. `JamesIves/github-pages-deploy-action` stays at v4.4.1 on purpose: Dependabot will propose the bump in a pull request of its own, where the owner can read what changed in the action that writes his site. The `CNAME` in `gh-pages` survives every deploy as measured, but whether the action or GitHub keeps it was not read: if the custom domain ever drops after a deploy, `clean-exclude: CNAME` on the action is the first thing to try.
- 2026-10-21 — **Dependabot follows C20** (`second-brain`'s spec, after red Dependabot PRs piled up across the portfolio): monthly, a 7-day cooldown (30 for a major), one `minor-and-patch` group for production and development together, a `security` group, at most three other majors open; npm at `/` and GitHub Actions only (no Dockerfile). No family group: none of the template's families is used here, and Biome is one package. The weekly `dev-dependencies` group (split by `dependency-type`, which C20 forbids) is gone, and so is the `@types/node` ignore — `@types/node` is not a dependency here. **`puppeteer-core` majors are held** by an `ignore`: `chrome-aws-lambda` 10.1.0, the last ever published, peers on `puppeteer-core ^10`, so #5 (→ 25.14.0) failed `npm ci` with ERESOLVE and was closed. **Lift** when the Mac preview script drops `chrome-aws-lambda` (moving to `puppeteer-core` current changes the script's API) — the owner's call. `sketch-gallery`, a git dependency, is never raised. No auto-merge.
